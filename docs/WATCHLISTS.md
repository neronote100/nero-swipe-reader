# ウォッチリスト・タグ取得・並び順の使い方（v0.6.0）

## リストを切り替える

「城下町メンバー」と「リスト1」〜「リスト10」の合計11枠を使えます。各リストは最大200人まで保存できます。選択欄で切り替え、「名前を変更」で分かりやすい名前を付けてください。

v0.2.1以前の登録は「旧ウォッチリスト」に自動移行します。既存の返信下書きも引き継ぎます。登録内容は、ログインしているnoteアカウントごとに利用中のブラウザーの端末内へ保存します。

## 用意済みの設定ファイルを登録する

1. 同じブラウザーでnoteへログインし、リーダーで「再確認」を押します。
2. 「読み込み」から、別途渡されたウォッチリストのJSONファイルを選択します。
3. ファイル内にリストIDがある場合はその枠へ、ない場合は現在の枠へ追加します。同じユーザーIDは重複登録しません。他のリストは変更しません。
4. 「新着記事を取得」を押します。

ファイルに`owner`がある場合、そのnoteアカウントでのみ読み込めます。会員名簿は公開ソースや配布ZIPに同梱していません。利用中のブラウザーの保存領域へ開発者が遠隔書き込みする機能もありません。設定ファイルを一度読み込むと、次回以降も登録内容が保持されます。

「保存」は選択中のリストをJSONで書き出します。返信下書き・コメントの送信履歴・認証情報は含みません。会員名簿を含む場合は、バックアップや共有の保管先を確認してください。

## 通常の記事取得

選択中のウォッチリストの各ユーザーから最大3本ずつ集めます。初期状態では「スキ済みの記事も含める」はOFFです。新しい記事から順に調べ、スキ済みを飛ばして未スキ記事が3本になるまで古いページも探します。3記事を見て終わる方式ではありません。

チェックをONにすると、各人のスキ済みを含む最新3本を集めます。チェック変更は次の取得に適用されます。取得中に条件を変えると、古い結果は表示せず中断します。

## 深掘りモード

1. 「深掘りモード」を開きます。
2. 読みたい人のnoteユーザーIDまたはプロフィールURLを1つ入力します。ウォッチリストへの登録は不要です。
3. 「スキ済みの記事も含める」を選択します。OFFなら未スキ記事が50本になるまで探し、ONならスキ済みを含む最新50本を集めます。
4. 「この人の記事を最大50本取得」を押します。

通常と深掘りのチェックは独立していて、前回の条件と深掘り対象はアカウント別に保存します。

## ハッシュタグの記事を取得する

1. 「ハッシュタグで企画・イベント記事を探す」を開きます。
2. `#企画名`、`＃企画名`、タグ名だけ、または `https://note.com/hashtag/企画名` のようなnoteのタグURLを1つ入力します。
3. 上限を50・100・200本から選びます。初期値は100本です。
4. タグ専用の「スキ済みの記事も含める」を選び、「このタグの記事を取得」を押します。

noteのタグ別記事一覧APIを使い、指定したタグが付いた公開記事を取得します。ウォッチリストの登録に関係なく、note全体から該当する書き手の記事を集めます。

チェックは通常取得・深掘りと独立しています。OFFならスキ済みを飛ばして未スキ記事を上限まで探し、ONならスキ済みを含む新しい記事から取得します。記事不足・スキ状態不明・通信失敗・探索上限・中断などによって、指定本数より少なくなる場合があります。上限に達しても未取得の記事が残る場合があり、タグ全体を網羅する機能ではありません。

## 並び順を切り替える

記事リーダーの「並び順」で、次の3通りを選べます。

- ランダム：取得時に作ったランダムな並びで表示します。
- 投稿日時：新しい順（降順）：新しい投稿から表示します。
- 投稿日時：古い順（昇順）：古い投稿から表示します。

投稿日時は年月日と時分秒まで比較します。日時不明の記事は昇順・降順どちらでも最後に置き、同じ日時の記事は取得時の並びを保ちます。

並べ替えでは記事を再取得せず、読んでいる記事と本文の位置を保ちます。リンク先を開いている場合も表示中の記事と戻る履歴を保ちます。「古い順」も今回取得した記事の範囲内での順序です。表示順を変えても取得対象や上限は変わりません。

通常・深掘り・タグ取得に共通して使えます。選んだ並び順、タグとその取得条件は、アカウント別に端末へ保存します。

## 取得と表示の共通事項

- 読み取り対象はnoteの公開記事一覧です。本文はログイン中の利用者が取得できる範囲だけ表示します。
- 取得時は対象全体をランダムに並べます。初期の並び順はランダムで、取得後に投稿日時順へ切り替えられます。登録順・通信完了順をランダム表示の順序には使いません。同じ著者が偶然続く場合はあります。
- スキ済みを含めない場合、スキ状態を確認できない記事は未スキ扱いにせず除外し、次の記事を探します。スキ済みを含める場合は状態不明を理由に除外しません。
- 記事が少ない、未スキが足りない、通信に失敗した、探索上限に達した場合などは、通常の3本・深掘りの50本・タグの設定上限より少なくなることがあります。本数と不足を画面へ表示します。
- 通常・深掘りは1人につき最大1000ページ、タグ取得は最大100ページまで探索します。通信の失敗が続く場合はその人の探索を停止します。上限や失敗による途中結果を完全取得扱いにしません。
- 「記事取得を中断」で止められます。途中で確定できた記事は表示します。リスト・取得条件・対象を変えた場合は古い応答を破棄します。

Chrome版では、ログインした同じプロフィールのnoteタブとリーダータブを両方開いたまま利用してください。導入・更新は [Chrome版の導入手順](CHROME_INSTALL.md)、Firefox版の配布は [Firefox版の手順](MEMBER_RELEASE.md) を参照してください。

## 手動で追加・修正する

ユーザー名またはnoteのプロフィールURLを入力して「追加」を押します。「×」は現在のリストからだけ削除します。ID未照合のメモがある場合は「IDを登録」から確定したユーザー名を入力できます。名簿はウォッチ対象であり、有効なメンバー資格を自動判定する仕組みではありません。

## 設定ファイルの例

```json
{
  "format": "nero-watchlist",
  "version": 1,
  "owner": "your_note_username",
  "list": {
    "id": "castle",
    "name": "城下町メンバー",
    "users": ["example_creator"],
    "pending": []
  }
}
```

`castle`が城下町枠、`list-1`〜`list-10`が追加枠です。これは形式説明用のダミーデータです。


## 記事内のリンクを読む

本文中のnote記事リンク・リンクカードを押すと、Swipe Reader内にリンク先の記事を表示します。「リンク元へ戻る」で元の記事と読んでいた位置へ戻れます。複数の記事をたどった場合も1つずつ戻れます。ウォッチリストの並びや位置は変更しません。

リンク先の表示中は、リストの前後移動・スワイプは停止します。元へ戻ると通常の前後移動を再開します。スキ・「コメント」は現在表示している記事が対象です。別の記事で既に開いた下書きは宛先を保持するため、リンク先に新しくコメントする場合はその記事の「コメント」を押してください。

外部サイトやnoteの記事以外のページは別タブで開きます。Ctrl／Command＋クリックなどブラウザー標準の新しいタブ操作も使えます。本文の見出しへのリンクは同じ本文内で移動します。

noteカードのタイトル・画像等は表示位置へ近づいた際に取得します。情報を取得できなくてもリンクは残します。外部サイトのプレビュー情報を取得するための通信は行いません。動画などの埋め込みは直接実行せず、安全なリンクとして表示します。
