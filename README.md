# NERO Swipe Reader — Firefox / Chrome メンバー版

noteのウォッチリストをスワイプしながら読み、記事を開いたままコメントに返信できるブラウザー拡張です。Firefox版とPC向けChrome版があり、画面・スクリプトは拡張内に同梱しています。GitHub Pagesや専用サーバーを必要としません。

## できること

- 利用者ごとのウォッチリスト11個（城下町メンバー＋自由に使える10個、各最大200人）。ユーザー名またはnoteのURLから追加。
- 各書き手の新しい記事からスキ済みを飛ばし、未スキ記事を最大3本ずつ集めてランダム表示。スキ済みを含める切り替えにも対応。本文・画像を読み、上下スワイプ・矢印キー・前後ボタンで切り替え。
- 深掘りモードで1人を指定し、最大50本の記事を取得。スキ済みを含めるか選択可能。
- 記事内のリンクカードを表示。note記事はリーダー内で開き、リンク元の読んでいた位置へ戻れる。外部サイトは別タブで開く。
- 利用中のブラウザーのnoteログイン状態を利用した、記事へのスキ・コメント・返信。
- 自分の記事を走査し、未返信コメントを一括取得。進捗・途中保存・中断・差分更新・全件再確認に対応。
- 記事閲覧と返信欄を並べて表示。スマートフォンでは縦に配置。下書きはアカウント別・コメント別に端末へ保存。
- 送信前にログイン中のアカウントを再確認。通信結果が不明な投稿を自動再送せず、24時間の重複防止情報を保存。

「未返信」は同じスレッドで自分の最後の返信より後に届いた他の人のコメントです。ログイン中の本人がスキ済みのコメントは、返信していなくても取得・表示対象から除外します。返信後は該当コメントを一覧から除外し、次の一括取得でスレッド全体を再判定します。

## Chrome版の無料配布・導入

配布用ZIPを解凍し、PC版Chromeの `chrome://extensions` で「デベロッパーモード」をONにして「パッケージ化されていない拡張機能を読み込む」からフォルダーを選択します。Chrome Web Store登録・Googleへの登録料・Mozilla署名は不要です。

[Chrome版の導入・更新手順](docs/CHROME_INSTALL.md) / [配布ZIP](downloads/v0.5.1/nero-swipe-reader-0.5.1-chrome.zip)

Chrome 120以降（最新版を推奨）のWindows・Mac・Linux向けです。Android・iPhone版Chromeには導入できません。長い取得は開いているリーダータブで実行し、同時に有効なリーダーは1つです。同じChromeプロフィールでログインしたnoteタブを開き、noteタブとリーダータブの両方を閉じずに利用します。他のタブでの作業は可能です。更新は手動でファイルを差し替えて拡張を再読み込みします。

```bash
npm run package:chrome
```

`dist/chrome-members/`、`dist/nero-swipe-reader-0.5.1-chrome.zip`、再ビルド用の `dist/nero-swipe-reader-0.5.1-chrome-source.zip` を生成します。

## Firefox版の開発用インストール

```bash
npm run package:members
```

PC版Firefoxの `about:debugging#/runtime/this-firefox` →「一時的なアドオンを読み込む」から `dist/firefox-members/manifest.json` を選択。ツールバーの拡張アイコンでリーダーを開きます。同じFirefoxでnoteへログインして「再確認」を押してください。

一時読み込みはFirefoxの再起動で解除されます。生成される `dist/nero-swipe-reader-0.5.1-unsigned.zip` はMozilla署名前の開発用です。通常のPC版・Android版Firefoxへの配布には署名済みXPIが必要です。

## Firefox版のメンバー配布まで

1. [配布・実機確認手順](docs/MEMBER_RELEASE.md)に沿って、PC版とAndroid版Firefoxで確認。
2. Mozilla Add-on Developer Hubで既存アドオンの新しいバージョンとして生成ZIPを提出し、署名済みXPIを取得。初回から限定配布する場合は「このサイト以外で配布」を選択。
3. 署名済みXPIをメンバー向けの配布先へ掲載。

現時点では自動検査済みの開発版です。実際のnoteログイン・投稿、実機操作、Mozilla署名は未確認です。noteの非公開APIを利用するため、note側の変更に応じた保守が必要です。有料本文はログイン中のアカウントに取得権限がある範囲のみ表示します。

拡張だけでメンバー資格を認証する仕組みはありません。メンバー限定配布は配布先で管理してください。配布ファイルの再共有を技術的に防止するものではありません。

## 検査

```bash
npm run check          # 旧版の回帰検査
npm run check:members  # メンバー版のビルドと動作検査
npm run package:members
npm run check:chrome   # Chrome版の起動・通信・生成物検査
npm run package:chrome # 共通検査とChrome配布ZIPを生成
```

送信処理・現在のアカウント確認・重複防止・下書き識別・スワイプ判定・接続元制限・未返信判定を、noteへ実投稿せずに検査します。

[プライバシー方針](members/PRIVACY.md) / [旧版の説明](docs/LEGACY_README.md)

旧版のPages・自動運転コードは移行元の履歴として保持しています。メンバー版には自動運転・スキ返し・特定マガジンへの追加機能を組み込んでいません。

## v0.2.1 の変更

本人がスキ済みのコメントは、新規取得と保存済み一覧の両方で除外します。他の人だけがスキしたコメントや、スキ済みコメントへの未対応の返信は対象に残ります。更新後に「一括取得」でnote上の最新状態を反映してください。除外後にスキを解除したコメントを戻す場合は「全記事を再確認」を選びます。

[Google Play／App Storeへのアプリ化：費用・手続き・課題](docs/STORE_PUBLISHING_PLAN.md)

## v0.3.0 の変更

- 「城下町メンバー」と10個のリストを保存・切り替え。リスト名の変更、JSON読み込み・保存に対応。
- 旧ウォッチリストは「旧ウォッチリスト」に自動移行し、下書きも保持。
- 各ユーザーの公開記事一覧の先頭ページから公開日時順の直近3記事を取得し、本人のスキ済み記事を除外。4記事目以降からの補充は行わない。
- スキ状態はキャッシュを使わず確認し、不明・失敗の記事は未スキ扱いにせず除外して件数を表示。
- 全員の確認が終わってから対象全体をシャッフルし、登録順や通信の完了順に依存しない並びにする。偶然同じ著者が連続することはある。
- 長い取得の進捗と中断に対応。取得中にリストを変えても、前のリストの記事は混入しない。

会員名簿は公開ソース・配布ZIPに同梱せず、個別のJSON設定ファイルを「読み込み」から取り込む。設定は端末内・アカウント別に保存される。自分のリストは「保存」でバックアップできる（会員リストを共有する場合は共有先に注意）。JSONの `owner` がある場合は同じnoteアカウントだけで読み込める。

## v0.3.1 の変更

- 返信待ちコメントに「コメントにスキ」を追加。本人がスキしたコメントは対応済みとして一覧から除外。
- 返信欄に「返信先のコメントにもスキを送る」（初期ON）を追加。「返信＋スキを送信」で、返信に続いて元コメントへスキを送信する。OFFなら返信のみ。
- 返信とスキは別の通信。返信済み・スキ未完了を区別し、未完了のスキは端末内へ保存。「スキのみ再試行」は返信本文を再送しない。
- 子コメントへの返信でも、スキは親コメントではなく、その子コメント自身に付ける。
- スキの送信結果が不明・重複応答の場合は、本人の対象コメントのスキ状態を読み直して確認する。確認できなければ成功扱いにしない。

実際のnoteアカウントでの新機能の送信確認とv0.3.1のMozilla署名は未実施です。

## v0.4.0 の変更

- 通常取得は「直近3記事から除外」ではなく、新しい記事から順に調べて未スキ記事を最大3本集める。スキ済みの記事が続く場合は古いページまで探す。
- 通常の「スキ済みの記事も含める」をONにすると、スキ済みを含む最新3本ずつを取得。
- 深掘りモードはユーザーIDまたはプロフィールURLから1人を指定し、未スキ記事を最大50本集める。深掘り側のチェックをONにするとスキ済みを含む最新50本が対象。
- 両モードで取得結果全体をランダムに表示。チェック状態と深掘り対象はアカウント別に保存する。
- 記事不足・取得失敗・スキ状態不明・探索上限・中断で目標に届かなかった場合は、途中結果と不足を表示する。通信障害が続く場合は過剰な再取得を止める。

[ウォッチリストと深掘りの使い方](docs/WATCHLISTS.md)


## v0.4.1 の変更

- 記事本文で消えていた埋め込みリンクをカードとして表示。noteのリンクは、表示位置に近づいたカードからタイトル・画像・概要を補完する。
- noteの記事リンクはリーダー内で開き、「リンク元へ戻る」で元の記事とスクロール位置へ戻る。元のフィードの並びと位置は保持する。
- リンク先の記事でもスキ・コメントを送れる。埋め込み記事IDだけのリンクは正式URLを確認してから送信を有効にする。
- 外部サイトや記事以外のnoteページは別タブで開く。外部サイトの情報収集は行わない。本文の同一記事アンカーにも対応。
- 元の記事で既に開いた下書きの宛先は保持する。リンク先にコメントする場合はリンク先の「コメント」を押す。

実際のnoteアカウントでの表示・投稿、PC／Android実機とMozilla署名は別途確認が必要。

## v0.5.0 の変更

- PC版Chrome向けManifest V3パッケージを追加。デベロッパーモードでZIPを解凍して無料導入できる。
- 長時間の取得・送信処理はリーダータブで実行し、サービスワーカーの停止に依存させない。タブの終了・再読み込みで処理は停止するため、取得中は開いておく。
- Chromeでは同じプロフィール内でリーダーを1つだけ有効にし、アイコンを押すと開いているリーダーへ戻る。複数ページから同時に投稿することを防ぐ。
- Chrome配布用の公開キーを固定し、更新後も同じ拡張IDを保つ。更新手順と通信・保存内容を配布ZIPの `INSTALL.md` に同梱する。
- FirefoxとChromeの画面・機能を共通のソースから生成し、ブラウザーごとのログインとローカル保存を使う。ウォッチリストはJSONで移せる。
- ZIP生成はNode.js組込機能だけで行い、追加の圧縮ツールやGitチェックアウトを必要としない。


## v0.5.1 の変更

- Chromeの通信を、開いているnoteタブの同一オリジン内で実行する方式へ変更。拡張ページからの認証付き通信がCookie制限等で失敗する場合に対応する。
- ログイン確認だけでなく、記事・コメント取得と投稿も同じnoteタブ経由に統一する。タブを閉じる・note以外へ移動した場合は停止し、別のタブへの投稿を自動再試行しない。
- Chrome権限に`scripting`を追加。対象は既存の`https://note.com/*`だけ。Cookie値の読出し・書出し・開発者への転送は行わない。
- noteタブがない、サイトアクセスを許可していない、HTTP 401／403／429、通信失敗、タイムアウトなどを区別して表示する。HTTP 403を未ログインと決めつけない。
- ログイン確認を毎回やり直し、アカウント切替・送信前の照合・重複投稿防止を維持する。

更新時はリーダーを閉じ、同じ保管フォルダーへ新版を上書きしてChromeの拡張機能を再読み込みする。続いてログイン済みのnoteタブを開いたままリーダーの「再確認」を押す。
